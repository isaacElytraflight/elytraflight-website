Part 1.1 — Convolutions from scratch

The first task was to implement convolution two different ways! The first way is with 4 for loops. This is a good way of visualizing how the math behind convolution actually works, but it is extremely slow, because it doesn't take advantage of OpenCV's paralellization or linear algebra speedups: 

def convolve4ForLoops(img, filter):

    imgShape = img.shape
    filterShape = filter.shape
    I, J = imgShape[0], imgShape[1]
    K, L = filterShape[0], filterShape[1]

    newImg = np.zeros((I+K-1, J+L-1))
    newImgShape = newImg.shape
    #4 for-loop image convolution

    def getImgVal(a, b):
        if a >= 0 and a < I and b >= 0 and b < J:
            return img[a][b]
        else:
            return 0

    for i in tqdm(range(I+K-1)):
        for j in range(J+L-1):
            value = 0
            #pixel value at (i, j) is sum(sum(cross correlation of flipped, shifted filter))
            for k in range(K):
                for l in range(L):
                    #img: (i-k, j-l)
                    img_value = getImgVal(i-k, j-l)
                    value += img_value * filter[k][l]

            newImg[i][j] = value
    return newImg

We see a few interesting things from this implementation. First, that I'm implementing "full" padding--that is, every single pixel in the image gets covered equally, by padding with [filter size-1] zeros on each side. I made a helper function called getImgVal to help with padding, since I didn't want to bother with padding the original image.

Also, we can see that the final result has the size [filter size + image size -1] on both axes.

Finally, we see how the internal system works: query the image at the outer loop's i, j values, shifted backwards by k and l; whereas the filter value is shifted forwards by k and l. This matches how convolution flips the filter:

(f ∗ g)[n] = Σk f[k] g[n − k]

Next, we see the two-for-loop version. For this, I took a relevant slice of the image, flipped the filter, and just did an in-place cross correlation with numpy: 

def convolve2ForLoops(img, filter):
    imgShape = img.shape
    filterShape = filter.shape
    I, J = imgShape[0], imgShape[1]
    K, L = filterShape[0], filterShape[1]

    newImg = np.zeros((I+K-1, J+L-1))

    def getSlice(a, b):
        slice = np.zeros_like(filter)
        loweri = max(a, 0)
        startSliceI = loweri-a
        upperi = min(a+K, I)
        endSliceI = upperi-a
        lowerj = max(b, 0)
        startSliceJ = lowerj-b
        upperj = min(b+L, J)
        endSliceJ = upperj-b

        assert upperi-loweri == endSliceI-startSliceI
        assert upperj-lowerj == endSliceJ-startSliceJ

        slice[startSliceI:endSliceI, startSliceJ:endSliceJ] = img[loweri:upperi, lowerj:upperj]
        return slice

    flippedFilter = filter[::-1,::-1]

    for i in tqdm(range(I+K-1)):
        for j in range(J+L-1):
            relevantSlice = getSlice(i-K+1, j-L+1)

            assert relevantSlice.shape == flippedFilter.shape

            correlation = np.sum(relevantSlice * flippedFilter)

            newImg[i][j] = correlation

    return newImg

On my face down below for a box filter, the 4-for-loop convolution was the slowest, at 13 seconds. The 2-for-loop convolution was next slowest at around 2 seconds; finally, scipy.signal.convolve2d was almost instantaneous.

I handled boundaries a slightly different way than in the 4-for-loop convolution. I made a helper function called getSlice that ensured that, if the slice required by the convolution involved numbers outside of the original image's range, then it would just fill them with zeros. This meant that I didn't have to worry about array index out of bounds. Either way, the padding is still full, and the overall size of the result image is still (I+K-1, J+L-1).

Part 2.1 — Image sharpening

I found this to be one of the most fascinating parts of the project. To understand how the unsharp filter works, we need to briefly think in frequency space. Above, we showed that edges are typically where the highest frequencies reside. A typical image taken by a camera is a noisy mix of both low and high frequencies (contiguous objects and their borders). What the unsharp filter does is take these natural high frequencies in the form of edges and amplify them, to make the image look more sharp and crisp.

But, how do we find the high frequency data in an image? We can use the gradient like we did above, but another way is to just take the image and subtract out everything that is a low frequency. In other words, subtract the blurred image from itself. This yields the high frequency components. Then, we re-add the high frequency components to the original image with some modifier, and voila!

I used a multiplier of 3 for these images to exaggerate the effect of sharpening the image.

The other cool thing is that, since all of these filters are still linear operators, you can compose them into one kernel, where the original image is represented by a "unity" kernel (1 in the center of a bunch of zeros), and the blur is represented by a gaussian. This is similar to a Laplacian filter: Sharp peak in the middle surrounded by a negative Gaussian.

Next, as an experiment, I try to blur the Taj Mahal image, and then use the unsharp filter to bring it back into focus. This does not work very well at all. The reason for this is that Gaussian filters are a very strict low pass filter, meaning once you apply a Gaussian, it kills almost all the higher frequencies. Nothing you can do fully restores these higher frequencies. Notably, this differs from a real-life blurry picture, where the higher frequencies are still present, but diminished.

Upon recombining them, you get a hybrid image! It works because you tend to focus on high frequency data close up, and can only see low frequency data from far away.

Part 2.3 — Gaussian and Laplacian stacks

Now we finally reach the final part of this project. The idea for the Gaussian stack is fairly straightforward: continually blur the image more and more. One must take care, though: since we aren't downsampling like we would with a pyramid, we have to blur a lot more to get much of a difference between layers of the stack. I set the standard deviation of the gaussian filter to be exponential relative to the layer number, with some hyperparameter configs for how much blurring to start off with and how quickly to grow. If you don't set exponential SD, the blurriness only grows linearly, which is way too slow for this algorithm to work efficiently.

The Laplacian stack is very similar: just the differences between consecutive Gaussians, with the bottom of the Laplacian stack being the final Gaussian. That allows you to theoretically reconstruct losslessly the original image from the Laplacian pyramid.
