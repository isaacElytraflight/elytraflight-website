A.2 — Recover homographies

Here are some examples I generated in python of the correspondences between the pairs of images. It's immediately easy to tell that these will mainly require translation, as all of the correspondence lines between key points are parallel! We can see that the calculated homography matrices match this expectation: the 2x2 transformation matrix in the top left of each homography matrix is within 1% of the identity matrix. That means we're left with just the x/y translation.

In order to calculate the homography matrix, I used least squares: If y = Hx, where y is the image 1 (destination of warp) and x is the image 2 (source of warp), then x.T * H.T = y.T. So I ran the least squares numpy algorithm on x.T and y.T!

A.3 — Warp the images

This next part was fun. I got to practice rectifying objects back into squares by using the homography transformations from earlier! I draw red boxes around the squares in question, to show that they are indeed rectangular. The poster one was a tiny bit off, because my clicking of the key points was slightly inaccurate. But, overall, I was really impressed with the results!

The hardest part of the process was figuring out what bounds to make the destination image. Like the spec suggested, I used H to pipe the edges of the source image to coordinates in the destination image, and then make a bounding box. The only problem was how to handle negative coordinate values--this required some careful math to keep everything positive. This will come up again in the stitching part.

Also, I encourage you to look closely and compare the different types of interpolation I implemented. Both run off of a similar algorithm: for each point in the destination image, use H^-1 to convert back to a coordinate in the source image; if it's within bounds, then find the right value, and apply it to the destination image. Finding the right value is the tricky part.

Nearest neighbor just grabs the closest pixel in the source image by rounding the pixel values. Bilinear interpolation, on the other hand, required some careful modular arithmetic to use the relative closeness to the 4 nearest neighbors as weights to do a weighted average (my implementation is in the code).

Nearest neighbor is a lot faster, since it doesn't require polling 4 values and doing an interpolation between them for each pixel; but, on the other hand, it's a lot grainier. The benefit of bilinear interpolation is that it solves the problem of jagged edges reasonably well, especially when images are being rotated at strange angles, resized, or sheared.

A.4 — Blend the images into a mosaic

Now we reach the end! Since I already had image warping working correctly, the hardest part was tackling blending and making sure the warped images aligned properly. There were a lot of edge cases to handle, since it wasn't guaranteed where (0, 0) would be, on either the source or the destination image. Whichever image had a smaller minimum value (often negative) for the top left corner, needed to become the top left corner. Similarly, whichever image stuck out furthest to the bottom right needed to become that corner. It was a difficult problem to master, but ultimately I got it working!

I used a funny heuristic to alpha-blend the images. I found a solution that worked really well, which is doing a weighted average between the two alphas at every pixel where there is overlap; the way I calculated alpha is having an inverse relationship with respect to distance, falling off as the cube of the euclidean distance from the center of the image in question. This helped smooth out large changes while effectively keeping high frequency details.
