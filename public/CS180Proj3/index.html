Fun with Flow Models

This project is probably my favorite college CS project ever (maybe besides the RISC V CPU design in CS61C, or the World Builder in CS61B). I feel like the idea of flow matching to generate new images from noise is such a crazy and fascinating concept; it's like learning to write and perform arcane spells. It's one of those concepts to me that makes total sense in theory, but feels like it has no business actually working in practice. And, yet, it does.

In this project we started with noising and denoising images, using a combination of classical denoising techniques and pre-built flow matching models. This helped me gain an understanding of the different types of problems flow matching can be used for. That was part A. For part B, I actually trained my own classical denoiser, and more importantly, two different types of flow matching model.

A flow matching model is a neural network that learns to approximate the "flow" from random noise to the "manifold" of "desirable images". I put these in air quotes because they're a bit mathematically hand-wavy, which is partly why it makes it so fun and interesting. Instead of training the model on pairs of images and labels, we instead train the model to "de-noise" data, predicting the change between the noise and the final image, based on some noisy version of that image and usually conditioned on a label of that image as well as the current noise level (time). This yields a vector field that helps us during inference "flow" from a completely noisy image to a "desirable image" that is on the manifold of good images, but has never been seen before (not in the training data).

Part A — Exploring the Power of Flow Models

1.1 — Constructing noisy training inputs

Here's an assortment of images with different amounts of noise. One notable difference is that this is an interpolation between the final image and noise, rather than adding the noise directly on top of the image. This is the same way flow matchers add noise. 

def interpolate(image, noise, t):
    return (1-t)*noise + image*t

1.2 — Classical denoising

Gaussian blur denoises the images, but it also blurs them. Clearly we can't just throw the noise through a low pass filter and expect all our problems to go away.

1.3 — One-step denoising

In 1.3, I use one step of flow matching to denoise the image. In other words, rather than following a curved vector field trajectory from the noise back to the original image, I take one velocity approximation, and shoot directly back to the "denoised image" manifold. It works surprisingly well, but the more noise there is to begin with, the more the final version is blurred or lacks detail. 

def one_step_denoise(x, t, condition, predict_velocity):
    return x + (1-t) * predict_velocity(x, t, condition)

1.4 — Visualizing velocity

Here is a visualization of velocity, as well as the error between the prediction and ground truth. Note that the velocity is noisy and grey-ish; that's because it's the difference between the noise and the end result, so it shouldn't add too much extra energy to the noisy version of the picture; it also has to cancel out the noise.

When we compare the ground truth velocity with predicted velocity, we see the same phenomena we observed qualitatively in 1.3: with more noise in the image, the single-step flow denoiser fails to hallucinate back in details, and stays mostly generic.

1.5 — Iterative denoising with Euler sampling

Here's an example of iterative denoising, where we take a bunch of very small steps and continually recalculate velocity to more closely follow the curved vector field trajectory between the noisy version and the original image. We see that it has a very beneficial effect! Stuff in the one step denoise that was blurry has detail in the Euler version, because it allows the model to "hallucinate" details back in that seem reasonable for the context. And, of course, the gaussian blur looks horrible in comparison. 

@torch.inference_mode()
def euler_sample(x_start, t_start, step_size, velocity):
    t = t_start
    x = x_start.clone()
    samples = [(t, x.clone())]
    counter = 0
    while t < 1:
      h = min(1-t, step_size)
      x+= h*velocity(x, t)

      t+=h

      if counter % 5 == 4:
        samples.append((t, x.clone()))

      counter+=1

    samples.append((t, x.clone()))
    return (x, samples)

def cfg_velocity(x, t, condition, w, predict_velocity, null_condition=''):
    v_c = predict_velocity(x, t, condition)
    return v_c + w*(v_c - predict_velocity(x, t, null_condition))

3.3 — Visual anagrams

Here are some visual anagrams! These two pictures show different things when flipped upside down. The bottom one is a pencil sketch, so it's a bit faint, but on the right you can show how the "people" turn into leaves of the tree.

The way this works is by generating one flow velocity right side up, flipping it upside and generating a different prompted flow velocity, and then flipping it back around and averaging the two velocities. Honestly a genius idea. 

def visual_anagrams(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def v_func(x, t):
      v1 = guided(x, t, condition_a, w)
      v2 = rotate180(guided(rotate180(x), t, condition_b, w))
      v = 0.5 * (v1 + v2)
      return v

    final = euler_sample(noise, 0, step_size, v_func)
    return final[0]

3.4 — Hybrid images

I really enjoyed these hybrid images. They involve generating one flow velocity under a low pass filter, and another velocity under a high pass filter, and then averaging them! 

def make_hybrids(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def v_func(x, t):
      va = guided(x, t, condition_a, w)
      vb = guided(x, t, condition_b, w)
      v = lowpass(va) + vb - lowpass(vb)
      return v

    final = euler_sample(noise, 0, step_size, v_func)
    return final[0]

1.2.3 — Denoising pure noise

Here's an example of attempting to train a model on pure noise to detect digits. Obviously, it's not going to work. Neural networks work by extracting meaning from a complex collection of data. Pure noise is designed so that it has absolutely zero information. So, the best the model can do is average over all the training data, resulting in almost the exact same blurry blob for every test output.

The reason why it's struggling a bit, is that it's not conditioned on the type of digit, it's only conditioned on time. It also isn't using guidance, which puts it at a big disadvantage.
